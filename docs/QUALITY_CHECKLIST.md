# Quality checklist

## Definition of done

A task is done only when its acceptance criteria are met, the build passes, the result has been tested by actually using it, mobile and desktop have been checked, dark mode and RTL have been checked, there are no console errors, there are no unrelated changes, and the task is marked with evidence.

If a browser cannot be run, leave the task `[~]` with the exact note `needs visual check`; never mark it `[x]` on assumption.

## “Must not look AI-made” audit

### UI copy

- Use short, natural, Egyptian-friendly Arabic, the way a real shop writes: **أضف للسلة**, **اطلب على واتساب**, **المقاسات المتاحة**.
- Banned marketing filler: **ارتقِ بأسلوبك**, **تجربة تسوق استثنائية**, **اكتشف الأناقة**, `elevate`, `seamless`, `curated`, `unleash`, and `journey`.
- Avoid exclamation overload, emojis in the interface, title-case-everything, em dashes, robotic polite phrasing, and “Click here to buy”-style wording.

### Design

- No default purple/blue gradients.
- No three-icon-cards template.
- No random stock look.
- No inconsistent spacing or radii.
- No glass on everything.
- No fake stats or testimonials.
- No invented brand claims.
- Product photography and the considered image-slot states should carry the visual identity.

### Product text

- Write like a person describing real clothes: fabric, fit, and use.
- Keep descriptions short and avoid inflated adjectives.
- Sample products must be obviously samples.

### Code

- Use consistent naming.
- Comments are only for reasons that are not obvious; never write comments such as “this function does X”.
- No leftover debug logs or TODO spam.
- No placeholder names such as `foo` or `test123`.
- No dead code.
- No `Generated by`, AI, co-author, or similar wording anywhere in files.

### Commit messages

- Short, lowercase, natural developer wording.
- Never mention AI, generation, or authorship automation.
